# 红线、避坑与成稿自检清单


## 一、AI 产品简历五条红线

1. ❌ **不写和 AI 无关的经历**（纯 UI 设计、纯文案撰写、纯行政打杂）。
2. ❌ **不堆砌技术名词**（"精通 Transformer""会写 Python"——AI 产品不需要写代码，写了会被算法面试官追问到露馅）。
3. ❌ **不写模糊成果**（"提升了用户体验""获得了好评""效果显著"）。
4. ❌ **不虚构数据和经历**（包装得越完整，面试被追问风险越大；企业鼓励作品集，不等于鼓励精美故事）。
5. ❌ **不把"能运行"当"有产品价值"**（Demo 只证明功能能跑，不能证明有人需要；必须有用户验证、评测、失败案例、迭代）。

## 二、常见误区

| 误区 | 问题 | 正解 |
|------|------|------|
| 职责说明书式 | 只写"负责 XX 日常工作"，没写做成了什么 | 用 STAR/XYZ 写方法+结果 |
| 关键词堆在技能栏 | "熟悉 LLM、RAG、Agent"但经历里没有 | 关键词埋进行动和结果，一词一证据 |
| 一份简历投所有岗 | 每个岗都不够匹配 | 按方向做多版本，替换业务场景词 |
| 项目只有"做了什么" | 没有"解决了什么"，缺数字+结果+业务价值 | 每条 bullet 都要有量化或反馈证据 |
| 伪需求场景套大模型 | 计算器/固定表单等确定性场景硬塞 AI | 选 L2 真需求：非结构化数据、充满不确定性、传统方案难奏效 |
| 方案停留在对话框 | "用户输入→模型输出"简单套壳 | 写清工作流、工具调用、人工卡点、异常兜底 |
| 没有防御性设计 | 假装幻觉和延迟不存在 | 通过 RAG、异步处理、人工回环主动弥补 |
| 盲目追求项目数量 | 8 个潦草项目，面试官抓不到核心 | 一个闭环完整的胜过三个半成品 |
| 只晒工具操作截图 | 体现不出产品思维 | 展示决策：为什么用 AI、出错怎么办、效果成本如何取舍 |
| 个人评价空喊能力 | "沟通能力强、逻辑清晰" | 用经历和结果证明，自我评价只写总结+业绩+亮点 |

## 三、成稿自检清单（交付前逐项检查，全部通过才能交付）

### 匹配度检查
- [ ] 已解析目标 JD，列出三类关键词清单
- [ ] 简历中每个高频关键词都有对应经历证据
- [ ] 业务场景词与目标岗位一致（没有用错行业词）
- [ ] 无关经历已删除
- [ ] 版本方向正确（应用/增长/策略商业化）

### 结构与表达检查
- [ ] 篇幅 1 页 A4，模块顺序合理
- [ ] 个人评价包含"经验+结果+亮点"，无空泛形容词
- [ ] 每段经历有"项目背景/核心工作/项目结果"三段
- [ ] 每条核心工作以动词开头，写"方法+动作+对象"，非动词堆砌
- [ ] 概述句先给结论，重点前置

### 量化检查
- [ ] 每个项目结果都有数字、对比或外部评价
- [ ] 没有"效果显著""获得好评""大幅提升"等无基准表达
- [ ] AI 项目包含至少 2 类量化指标（准确率/完成率/耗时/成本/Bad Case 率/转化率等）
- [ ] 数据真实，未虚构

### AI 专业性检查
- [ ] AI 项目体现六类证据中的至少 4 类（问题/技术选择/工作流/评测/失败案例/迭代）
- [ ] 有模型边界、异常兜底或人机协同设计的描述
- [ ] 有 Prompt/Workflow/RAG/评测/Bad Case 中至少 2 项的具体实操
- [ ] 没有"精通 Transformer""精通 Python"等越位表述
- [ ] 没有把简单 Demo 包装成上线产品

### 红线检查
- [ ] 无个人/公司敏感信息泄露
- [ ] 无错别字、格式错乱、时间线矛盾
- [ ] 所有数据和经历经候选人确认真实

### 模板与数据完整性检查（基于已有简历/模板改写时必查）
- [ ] 严格保留了原简历/模板的排版布局、模块顺序、字体样式、表格结构，未新增/删除/调换模块
- [ ] 原有事实信息（姓名、学校、公司、时间、成绩、数字等）一字未改
- [ ] 没有编造任何数据、百分比、排名、奖项、公司或项目名称
- [ ] 没有"合理推测"或"美化"出候选人未做过的经历/成果
- [ ] 模板示例文字（xxx、XX 公司等占位符）已全部替换为真实信息或删除，无残留
- [ ] 缺失信息已向候选人追问，未用编造内容填充
- [ ] 交付文件格式与原文件一致
