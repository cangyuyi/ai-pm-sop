# 匹配诊断与多版本简历策略


## 一、五级匹配（面试官的衡量标尺）

面试官衡量候选人匹配度，从五个层级看，**能力匹配度是核心**：

1. **公司级别匹配度**：大厂/中厂/初创的履历对标。
2. **业务级别匹配度**：是否做过同类业务（电商/社交/教育/办公等）。
3. **行业匹配度**：对行业的理解深度。
4. **岗位经验匹配度**：是否做过同类型岗位工作（C 端/B 端、增长/策略/应用）。
5. **能力匹配度**（最核心）：是否具备岗位要求的硬技能与软技能。

> 趋势：过去极其关注稳定性，现在特别关注**能不能快速上手、解决问题**。

**策略含义**：
- 换赛道：用"可迁移能力"桥接，把过往经历重新包装成目标岗位需要的能力证据。
- 小厂进大厂：强化结果数据、标准化沉淀、复杂项目协同，弥补平台光环。
- 能力缺口：用相近证据替代（如没有 A/B 测试，就写"对照实验思维""前后版本对比"），或明确标注为待补，不虚构。

## 二、HR 扫读逻辑

校招旺季，HR 初筛一份简历平均 **10-15 秒**，只做三个判断：

1. **你和岗位匹配吗？**（看关键词、看经历方向）
2. **你真的做出过成果吗？**（看数字、看结果）
3. **你的逻辑清晰、做事有章法吗？**（看结构、看表达）

扫读时重点抓三类关键词：
- **你能做什么**：过去的经历/项目。
- **有没有成绩**：拿没拿到过结果。
- **有没有亮点**：大厂/知名项目/名校/差异化优势。

**写作含义**：简历必须"扫读友好"——模块清晰、重点前置、数字醒目、每段经历第一句话就点明价值。

## 三、诊断七维度检查清单（拿到旧简历时逐项扫描）

诊断不要只看关键词，以下七个维度都要检查。前四项是匹配度问题，后三项是表达/风险问题：

### 1. 关键词覆盖
- 列出 JD 三类关键词（硬技能/软技能/业务场景）清单
- 逐段扫描旧简历，标注哪些被回应、哪些缺失
- 特别注意高频词是否在简历最靠前的位置回应

### 2. 经历相关性
- 哪些经历与目标岗位无关（应删或弱化）
- 哪些经历体现了可迁移能力（应保留但换角度写）
- 是否有经历顺序错误（最相关的放最前面）

### 3. 量化充分性
- 哪些成果没有量化（应补数据或软证据）
- 哪些数据只有绝对值没有对比基线（"提升了很多"→需补前后对比）
- AI 项目是否至少有 2 类量化指标（准确率/完成率/耗时/成本/Bad Case率/转化率）

### 4. 能力证据一致性
- 哪些能力只在自我评价/技能栏里空喊（应移到经历里证明）
- 每个高频关键词是否有一段具体经历支撑（一词一证据）

### 5. 定位一致性（关键！）
- **身份标签是否统一**：全文强化的是同一个身份（AI PM），还是一会像运营、一会像设计、一会像开发？
  - 反面信号：技能栏大量罗列设计工具（PS/PR/剪映）+ 内容平台后台（小红书/抖音）→ 会被误判为运营
  - 正面信号：技能栏强调原型工具（Figma/Axure）+ 数据分析（SQL）+ AI 工具栈
- **经历叙事是否服务于同一个方向**：投 AI Agent 岗时，内容运营经历要写"用 AI 工作流提效"而非"粉丝涨了多少"
- **教育背景是否需要桥接**：非计算机/非产品相关专业，是否在教育段或个人评价中主动解释自驱学习经历

### 6. 时间线与真实性
- **时间线矛盾**：多段经历时间重叠是否合理解释（同时创业+实习+校园工作？）
- **教育时间**：入学/毕业时间是否与学历层次匹配
- **高风险数据标记**（面试大概率追问的数字，提醒候选人准备口径）：
  - 异常高的转化率/提升比例（如转化率45%、提升200%+）
  - 大样本量（如访谈150+人、服务10万+用户）→ 要确认是1v1访谈还是问卷/群聊
  - "精通/独立负责/主导"等强动词 → 确认实际贡献边界，面试会追问
  - 上线产品的用户量/收入 → 确认真实数据而非估算
- **敏感信息**：是否泄露公司机密数据（未公开的DAU、营收、客户名）

### 7. 排版与扫读友好度（纯文字诊断也应指出）
- **篇幅**：是否控制在 1 页 A4（约 600-800 字）
- **信息密度**：留白是否合理（建议至少 15-20% 留白，字号不要过小）
- **结构清晰度**：模块是否分明，每段经历第一句是否点明价值
- **重点前置**：概述句和核心数字是否在视觉上醒目
- **作品集/链接位置**：GitHub/作品集/Demo 链接是否放在头部（姓名行）而非埋在教育段末尾
- **错别字与格式一致性**：标点、日期格式、项目符号是否统一

### 诊断输出格式

诊断报告按以下顺序输出：
1. **匹配度总评**：高/中/低 + 一句话判断 + 最适合投递方向
2. **核心优势**：3-5 条，具体到哪里写得好（先说肯定，再提建议，用户接受度更高）
3. **问题与改进建议**：按严重程度排序，每条说清"问题是什么→为什么是问题→怎么改"
4. **改写优先级**：P0 必须改 / P1 建议改 / P2 锦上添花
5. **⚠️ 面试追问预警**：3-5 个简历上面试官大概率深挖的点，提醒候选人准备口径

## 四、为什么要做多版本

不同方向的 JD 关键词差异很大。一份简历投所有岗 = 每个岗都不够匹配。建议按方向准备 2-3 个版本。

## 五、三版本的前置经历与叙事主线

| 版本 | 前置经历（放最前） | 核心叙事主线 |
|------|-------------------|-------------|
| **AI 应用/Agent 版** | AI 工作流搭建、AI 评测、AI 调研、AI 产品 MVP | 场景 → Workflow/Prompt → 评测/Bad Case → 兜底 → 交付 |
| **AI 增长版** | 用户调研、内容运营、私域转化、AI 工具辅助增长 | 用户洞察 → 内容/渠道 → 私域承接 → 转化结果 |
| **AI 策略/商业化版** | AI 产品 MVP、需求验证、策略拆解、定价/交易 | 需求验证 → MVP 取舍 → 策略拆解 → 效果/收益意识 |

## 六、保留/删减决策原则

**保留**：
- 与目标方向关键词直接对应的经历。
- 有硬数据、有闭环、有失败迭代的 AI 项目。
- 能体现可迁移能力的经历（即使行业不同，但方法论相通）。

**删减/纠偏**：
- 与岗位无关的经历（如投 AI 应用岗时，把纯内容运营、纯采购经历弱化或删除）。
- 只写"熟悉 AI 工具"但无具体产出的泛化表述。
- 纯 SOP/执行类、无思考无结果的打杂内容。
- **不虚构**：未经验证的付费转化、留存数据、A/B 实验结果一律不写；MVP 阶段就如实写"处于 MVP/验证阶段"，真实交易证明来自其他经历就写其他经历。

## 七、证据缺口识别与补救建议

当 JD 关键词在候选人经历中找不到证据时：

1. **用相近证据桥接**：没有 A/B 测试经验 → 写"前后版本对比""对照实验思维"；没有电商经历 → 用私域转化/漏斗分析桥接。
2. **用项目快速补证据**（给候选人的建议，不写进简历）：
   - 缺 RAG 实操 → 做一个可展示的 RAG Demo：文档入库、切分/检索、回答、3 类 Bad Case 与评测表。
   - 缺 AI 评测作品 → 为现有 AIGC 项目建 20-50 条样例集与评测维度（正确性、完整性、可控性、格式合规、稳定性），记录 Prompt 版本与 Bad Case 变化。
   - 缺增长指标 → 建最小指标看板：触达数、完成访谈数、私域引流数、转化率、7 日二次互动。
3. **诚实留白**：补不了的缺口不要硬编，面试时如实说明并展示学习计划即可。

## 八、投递优先级（参考）

- **T0 主投**：与候选人证据链最完整方向匹配的岗位，用最对口版本。
- **T1 次主投**：可迁移能力强、缺口可桥接的岗位。
- **T2 选择性冲刺**：有一定 gap 但值得尝试的岗位，面试时主动说明阶段与计划。
