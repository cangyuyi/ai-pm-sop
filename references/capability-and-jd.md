# AI 产品经理能力模型与 JD 解析


## 一、核心人才画像

> **懂 LLM 应用落地，能够设计 Agent 与 AI 工作流，具备 C 端产品设计能力，同时理解用户增长、数据分析和商业化闭环的 AI 产品经理。**

AI 产品经理不需要写算法代码，但必须能：
- 判断**什么场景该用 AI、什么场景不该用**；
- 设计 **Prompt、工作流、知识库、人机协同边界**；
- 建立 **评测体系、Bad Case 闭环、兜底机制**；
- 用**数据驱动迭代**，对**效果与成本**做取舍；
- 推动**跨团队（算法/研发/运营/业务）落地**。

## 二、三大投递方向

当前 AI 产品校招/实习岗位主要归为三个方向，简历必须按方向调整侧重，**不能一份简历投所有岗**。

| 方向 | 核心定位 | 岗位典型名称 | 最看重的证据 |
|------|----------|-------------|-------------|
| **AI 应用 / Agent** | 把大模型能力做成可用产品 | Coze/飞书 AI 产品、RAG 产品、AI 助手、Agent 产品、创新工具 | Workflow/Prompt 实操、Vibe Coding/MVP、RAG/知识库、评测 SOP、Bad Case 闭环、兜底设计 |
| **AI 增长** | 用 AI + 数据驱动用户增长与转化 | 增长营销（AI 方向）、电商用户产品、搜索用户产品 | 用户洞察/访谈、内容/渠道实验、私域转化、数据复盘、A/B 测试、增长漏斗 |
| **AI 策略 / 商业化** | 策略规则设计与商业闭环 | AIGC 策略产品、商业化产品、策略产品 | 策略拆解、需求验证、MVP 取舍、定价/交易闭环、收益目标、对照实验思维 |

## 四、AI 项目/经历的"含金量"标准

这是区分"跑过 Demo"和"做过产品"的关键。候选人的每一段 AI 经历，都应尽量留下以下证据；撰写简历时要把这些证据显性化。

### （1）合格 AI 项目必须留下的六类证据

| 证据类型 | 具体要求 | 反面教材 |
|----------|----------|----------|
| **问题证据** | 访谈了谁、观察到什么行为、问题出现在哪个环节；3-5 个真实访谈胜过 100 份无筛选问卷 | 只写"用户有信息焦虑" |
| **技术选择** | 说清为什么用大模型，而不是搜索、规则库或普通表单 | 一个筛选器就能完成的任务硬塞聊天框 |
| **工作流** | 用户输入什么→模型调用什么数据/工具→哪步需人工确认→失败如何回退；必须讲清系统边界 | 只有"用户提问→模型回答"的简单链路 |
| **评测** | 至少一组小型测试集，记录任务完成率、准确性、响应时间、调用成本和典型错误；指标要和产品目标对应 | 没有任何量化评估，全凭主观感觉 |
| **失败案例** | 展示模型编造信息、遗漏条件或误解用户的真实过程，再解释改了什么（提示词/知识库/交互/工作流） | 没有失败记录（大概率只跑过演示样例） |
| **迭代结果** | 第一版和第二版改了什么、指标有无变化、哪些问题仍未解决；展示"判断—验证—修正"闭环 | 只说"项目做完了"，没有迭代过程 |

### （2）作品集/项目报告六段标准结构

简历中的项目描述虽然篇幅短，但内在逻辑应遵循这六段（可压缩，不可缺失）：

1. **业务背景**：真实可量化的痛点，避免宏大空洞场景。
2. **用户场景**：明确目标用户和 1 个高频核心场景，拒绝大而全。
3. **人机方案**：AI 与人的分工边界、人机回环、高风险场景人工卡点。
4. **AI 专项设计**：模型选型、Prompt 架构、RAG/知识库、上下文管理、工具调用设计。
5. **流程闭环**：需求输入→智能处理→结果输出的完整闭环，含异常兜底、故障恢复。
6. **量化复盘**：准确率、响应耗时、Token 成本、用户留存等可量化指标，迭代前后对比。

> **重点突出**：模型边界、异常兜底、提示词设计、数据指标评估这些 AI 专属能力；**弱化工具演示**（"会用 Coze/Figma"不是竞争力）。

### （3）Agent 项目六大核心含金量标准

1. **依托真实业务，拥有完整业务闭环**：从需求输入→智能处理→结果输出，切实降本提效。单纯一问一答只是聊天机器人。
2. **具备完整工程体系**：数据库设计、API 规范、权限管理、日志追踪、异常兜底、并发与会话管理。只会调模型写 Prompt = 玩具 Demo。
3. **任务规划与自愈能力**：自主拆解任务、工具调用失败自动重试纠错、结果核验；多 Agent 协同须贴合业务，不盲目炫技。
4. **精细化上下文工程管理**：精准调度当前任务、历史记忆、知识库、工具结果；分层筛选、精准投喂；防信息缺失与上下文污染。**面试高频考点**。
5. **可观测、可量化的评估体系**：追踪模型调用、工具链路成功率、响应耗时、Token 成本、结果准确率；构建金标准数据集，定义评估维度。
6. **人机协同与风险兜底**：高风险场景（资金、隐私、对外发文、关键审批）必须人工确认；置信度低自动触发人工介入。

### （4）四条竞争力检查

1. 有一个**核心含金量最高的模块**，而非堆量。
2. **多轮迭代且效果递增**，每版之间有数据支撑。
3. 覆盖**完整工作流**：需求分析→竞品分析→Agent 核心能力构建→评测。
4. 融入**今年竞争方向**：Skill、MCP、工具调用、短期/长期 Memory 等企业级落地能力。

> **趋势提醒（2026 秋招）**：AI Coding 普及使模板化 RAG/多 Agent 项目严重贬值；面试官不再问"你会什么"，只问"你优化了什么"（框架选型依据、架构取舍、耗时优化、兜底方案、评测体系、成本平衡）。真实实习/落地经历是核心壁垒。一个闭环完整、有数据、有失败案例的项目，胜过三个半成品。

## 五、JD 解析：三步挖词法

简历不是写你想写的，是写 HR 想看的。HR 看简历的本质是"找匹配"。

拿到一份 JD，分三类挖词：

| 词类 | 定义 | 举例 | 特点 |
|------|------|------|------|
| **硬技能词** | 岗位要求的具体工具、技术、方法 | SQL、Python、Axure、神策、Coze、Prompt 工程、RAG、A/B 测试、MCP | 有明确标准，是机器初筛核心匹配项 |
| **软技能词** | 岗位要求的能力特质 | 跨部门协作、用户洞察、逻辑思维、项目推动、数据分析、问题定位 | 必须用经历证明，不能只写在自我评价里 |
| **业务场景词** | 岗位所在行业、业务方向 | 电商导购、智能客服、企业知识库、AI 教育、AI 办公、内容社区 | 体现行业理解，让 HR 觉得"你懂我们的业务" |

**操作步骤**：
1. 通读 JD，把岗位职责和任职要求中的关键词逐句标出，归入上述三类。
2. 统计词频——反复出现的词是核心需求，必须在简历最靠前的位置回应。
3. 对每个关键词，盘点候选人是否有对应证据；有证据的埋入经历，无证据的标记为缺口。

## 七、关键词植入三原则

1. **自然不堆砌**：关键词要和动作、结果绑定。
   - ❌ "熟悉 SQL、Python、Prompt 工程"
   - ✅ "通过 SQL 提取用户行为数据，定位转化流失节点"
   - ✅ "建立 Prompt 版本台账，每版效果量化对比，Bad Case 率下降 X%"
2. **高频词前置**：JD 里反复出现的词，放在对应经历最靠前的位置（概述句或第一个动作）。
3. **精准不泛用**：投不同岗位要替换业务场景词。投电商岗写"导购转化率"，投办公岗写"办公效率/知识库命中率"，不能一份简历投所有岗。
